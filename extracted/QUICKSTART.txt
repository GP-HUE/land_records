An AI-powered, multi-user web application for digitizing legacy land records.

## WHAT'S NEW IN v3.12.0 (25-Sep-2026) — BULK OCR: MANY SCANS, ONE QUEUE
The Upload tab digitizes one scan at a time; a digitization drive has
hundreds. The new 📚 Bulk OCR tab processes a whole pile at once.
### 1) Multi-file batch upload (up to 25 scans / batch)
  * Drag & drop up to 25 PDF/JPG/PNG/TIFF files with ONE language +
    ONE document type hint (hint: same-type + same-language batches are
    ~2× faster and more accurate — the tab says so, bilingually)
  * Files enter a SQLite-backed server queue processed by a background
    worker through the SAME OCR pipeline as a single upload (OCR →
    extract → AI rescue → validation → duplicate check) — bulk never
    takes a shortcut
  * Live progress: per-file status (queued → processing → done/failed),
    progress bars per batch, auto-refresh; operator can keep working in
    other tabs; a refresh or app restart never loses a batch (items
    stuck mid-flight re-queue on boot)
### 2) Review table — every file pre-screened before it enters the register
  * Extracted survey/village/owner, OCR confidence, validation verdict
    and warnings per row, colour-coded
  * Duplicate detection in-table (matches an existing record → flagged,
    never silently double-imported)
  * ADMIN batches also get an instant 🛡️ SA CourtLink screen per row
    (stay orders / prior cases surface before import) — operator and
    verifier batches are never screened (admin-only feature, enforced)
  * Failed rows (e.g. a blank scan) get an OCR diagnosis and one-click
    Retry, optionally with a different language pack
### 3) Import — bulk never bypasses verification
  * ✓ Import all clean (N): one click imports every valid, non-duplicate
    row; 🟡 rows import individually with an explicit ⚠️ confirm
  * EVERY imported record lands in the verification queue as
    pending_review for the Verification Officer — the bulk path removes
    the typing, not the human check. Each import is audit-stamped
    'bulk_import' with its BATCH id, and a CSV batch report downloads
    for the office file
### Roles
Data operators, verification officers and admins can run batches (each
sees only their own; admin sees all). Viewers are locked out.
### Tests

English batch end-to-end (blank-scan failure, fields/confidence,

## WHAT'S NEW IN v3.11.0 (25-Sep-2026) — SA COURTLINK: DEMO COURT DATABASE + INSTANT CASE-HISTORY DETECTION
Real courts keep a case record for every disputed land parcel; until now the
portal only knew cases typed into it manually. SA CourtLink simulates that
external courts database and lets the Superior Administrator layer DETECT a
land's previous court-case history automatically.
### 1) ⚖️ Demo Court Database (admin-only) — button sits ABOVE the 🤖 assistant
  * Floating ⚖️ button (left, directly above the AI assistant) opens the
    predefined court-case database: case no., type, court, petitioner vs
    respondent, village/survey/khasra/owner, status (pending / STAY /
    decided / dismissed), filed year, next hearing, summary
  * Full ADD / EDIT / DELETE — create as many predefined cases as you want
    for demos; every change is audited (court_db_case_added/updated/deleted)
  * Seeded with 6 ready cases, incl. a STAY ORDER on Rampur Khas survey 145
    and a decided 2019 revenue case on the demo Barkheda survey-312 parcel
### 2) SA detection — record page asks "Do you want SA to detect predefined court cases?"
  * Open any record (admin): a 🛡️ SA CourtLink card asks exactly that —
    confirm and SA matches the record's OCR details (survey / khasra / owner
    / village) against the court database with graded confidence:
    EXACT (survey+village) · STRONG · PROBABLE (owner+village) · POSSIBLE,
    each with a human-readable match reason; precision-proven (a case on an
    adjacent survey number does NOT match)
  * Every found case has "➕ Attach to this record" — one click imports it
    into the record's litigation ledger (risk view, PDFs, transfer gate
    pick it up); duplicates are refused
  * The scan and the attach are written into the record's 📜 Audit Trail
    (sa_courtlink_scan / sa_courtlink_attach)
### 3) Instant on admin upload — and admin-only end to end
  * When an ADMIN uploads/processes a document, SA screens it IMMEDIATELY
    after OCR and a modal reports any prior court-case history found
  * Data ENTRY operators and VERIFICATION officers CANNOT access anything:
    no ⚖️ button, no database, no scan, no attach — server-side 403s back
    the hidden UI (verified by the test battery)
  * SA mode chat also understands "scan the court database for record <id>"
### 4) New demo scans (samples/)
  * khatauni_rampur_2025.png — matches the STAY order (admin upload → red
    SA modal instantly)
  * khatauni_guroli_2025.png — same-village near-miss stays CLEAN (Guroli
    survey 88 vs case on 87) → green "no prior case" result

  * verdict banner: 🔴 ACTIVE LITIGATION (pending case — must be cleared or
    disclosed before a transfer) / ⚠️ prior litigation, all closed /
    ✅ no court cases on record
  * ➕ Record a Court Case (Data Operator+) and ✓ Record Outcome
    (Verification Officer+ — decided/withdrawn/settled + decision summary);
    only an ACTIVE case can be closed (double-close refused)
  * the 🛡️ Fraud & Risk engine gained 3 new rules:
      🔴 ACTIVE_LITIGATION          a case on the land is still pending
      🔴 TRANSFER_DURING_LITIGATION a deed signed while a case was pending
                                     (a transfer during pending title/
                                     possession litigation is voidable)
      🔵 CLOSED_LITIGATION_ON_RECORD prior (now-closed) cases, for transparency

    case exists stamps "⚠ APPROVED WITH ACTIVE LITIGATION: <case> (filed
    <date>)" into the approval note + audit trail

### 2) 🛡️ Fraud & Risk Check — is this land/record fraud?
NEW. A local, rule-based engine over the land's full passbook (+ encumbrance

  * 🟠 AREA_JUMP — area changed >15% with no partition/merger on file
  * 🔵 REJECTED_CONFLICT_COPY — documented dispute (rejected conflicting
    record), shown for transparency
  * 🔵 CHAIN_GAP — big gap in the passbook
  Each flag has severity, a plain-language explanation and the evidence.
  Verdict: 🔴 encumbered / 🔴 critical risk / 🟠 review advised / 🟢 clear.

## Building the app .exe (Windows) — one-folder build

Double-click **build_exe.bat**. It creates the folder
`dist\LandRecordSystem\` with the app inside.

- **Run it from:** `dist\LandRecordSystem\LandRecordSystem.exe`
- **Why one-folder instead of one-file:** a one-file exe re-unpacks ~300 MB
  into a temp folder on EVERY start and must delete it on exit — that
  deletion is what caused the "Failed to remove temporary directory" popup
  (Windows/antivirus briefly locks files). One-folder mode has **no temp
  files at all**: the popup is impossible, and startup is much faster
  (a few seconds instead of 30 s - 2 min).
- No terminal window opens. On start you first see a small
  **"Land Record System - starting up"** window, then your browser opens
  **by itself as soon as the website is ready**. If the browser does not
  open, visit http://localhost:8000.
- Server log: `dist\LandRecordSystem\data\server.log`
- **NEVER delete the `dist\LandRecordSystem` folder** — your database
  (all accounts + records) lives in its `data\` subfolder.
- **Closing all browser tabs stops the server almost immediately** (within
  ~10-15 seconds) — just like closing the old terminal window. Double-click
  the .exe again anytime to start fresh; your data is kept.
  (The short grace only protects page refreshes: pressing F5 will NOT kill
  the server.)
- To stop it right now: Task Manager (Ctrl+Shift+Esc) → end
  `LandRecordSystem.exe` (there may be 2-3 of them: launcher, server,
  OCR engine — end all of them).

### Sending the app to a teammate

1. Select the whole `dist\LandRecordSystem` folder
2. Right-click → **Compress to ZIP** (or any zip tool)
3. Send the zip. They: **unzip anywhere → double-click
   `LandRecordSystem.exe`**. No Python or Tesseract install needed.
   First run may show SmartScreen "Windows protected your PC" →
   **More info → Run anyway** (normal for a free, unsigned app).

### Crash-proof by design (no file can kill the website)
The program runs in 3 layers:
  1. MONITOR  - watches the server; if the server ever dies, restarts it
                in ~2 s (your tab shows "reconnecting" and heals itself).
  2. SERVER   - the website (HTTP/SQLite only). It contains NO native OCR
                code, so a bad file physically cannot crash it.
  3. OCR WORKER - all OCR (OpenCV/Tesseract/PyMuPDF) runs here, in a
                disposable process. A pathological file can at worst kill
                the WORKER: that one upload gets a clean error, a fresh
                worker starts automatically, and the next file is fine.
                (The same file is even retried once automatically.)
Plus hard size limits: images above 15000 px on the longest side are
rejected before decoding (no out-of-memory kills), 10000-15000 px are
auto-downscaled.
- Task Manager note: you may see several LandRecordSystem.exe entries
  (monitor + server + OCR worker) - that is normal. End ALL of them to
  stop everything (or just close the browser tab - everything stops
  cleanly within ~10 s).

### "Windows protected your PC" (SmartScreen) — what to do
Windows shows this warning for any free, unsigned .exe. It is NORMAL, not a
virus. To run the app:
1. Click **More info** → **Run anyway**.
2. (For your team/IT) permanently allow it in
   **Windows Security → App & browser control → SmartScreen**, or have the
   organisation sign the exe with a code-signing certificate.

Alternative without the warning: run the app from `start.bat` (uses Python,
which Windows already trusts) instead of the .exe.

## Team accounts — important! (Why a teammate's login can fail)

**Every computer has its OWN database** (`data\landrec.db` next to where you
run the app — for the .exe that is `dist\data\landrec.db`). Accounts created
on one computer do NOT exist on another computer.

So if you create an account and share its email/password with a teammate but
they run their own copy of the app, their login will say
"no account with this email" — and only the default admin works.

Correct workflow for a teammate:
1. Your teammate runs the app on **their** computer.
2. **Option A (easiest — account export/import):** On your computer, open the
   **Users tab → ⬇️ Export** (downloads `landrec-accounts.json`). Send that
   file to your teammate. On **their** computer, open **Users tab → ⬆️ Import**
   and pick the file. Their account now exists on their computer.
   **Option B:** You (admin) log in on THEIR computer (or remote in), open
   **Users tab → Create User**, and create their account there.
3. If a teammate forgets their password: **Users tab → 🔑 Reset Password**
   on that same computer. The reset is recorded in the audit log.

Security notes (this build):
- Anyone can self-register — new accounts always start as Data Operator
  (least privilege). The System Administrator promotes them to
  Verification Officer / Admin from the Users tab.
- Passwords: minimum 8 characters, must contain a letter and a number/symbol,
  stored as PBKDF2-SHA256 (200,000 iterations) — never in plain text.
- 5 wrong logins per email → 5-minute lock; per-IP rate limits on login and
  OCR upload (10/minute).
- Session tokens: HttpOnly cookie + Authorization header (the secure
  channels). A ?token= query fallback is kept ONLY as a last resort for the
  sandboxed live-preview iframe (which strips the Authorization header);
  the real .exe (localhost) uses the secure cookie/header channels.
- Uploaded files: size/type validated, stored under random names.
- Sample-file endpoint: strict filename check (no path traversal).
- Full audit trail of logins, verifications, corrections, password resets,
  account exports/imports.
- Share accounts between computers with Users tab → ⬇️ Export / ⬆️ Import
  (a portable JSON file with password hashes — send it to the other PC).
- If you deploy over HTTPS (reverse proxy), session cookies are automatically
  flagged `secure`.

## Troubleshooting

- "OCR failed" → Tesseract is not installed or not on PATH. Install it, or set
  the `PYTESSERACT_PATH` environment variable to tesseract.exe's full path.
- Port 8000 already in use → the .exe now shows a dialog; with start.bat, edit
  the `--port 8000` in start.bat/start.sh.
- To reach the app from another computer on your network, use your machine's
  IP instead of localhost, e.g. http://192.168.1.50:8000
- The .exe seems to "do nothing" → check Task Manager for
  `LandRecordSystem.exe`; server log at `dist\data\server.log`.
- "Failed to remove temporary directory" popup → only possible with OLD
  single-file builds (they unpack a temp folder and must delete it on
  exit). This build is **one-folder**: no temp folder exists, so the popup
  cannot happen. If you still see it, you are running an old exe — close
  it, rebuild with the current build_exe.bat, and run
  `dist\LandRecordSystem\LandRecordSystem.exe` from the new folder.
